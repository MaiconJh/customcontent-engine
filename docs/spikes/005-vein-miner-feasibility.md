# Spike 5 - Vein Miner Feasibility

Status: In Progress  
Date: 2026-06-26  
Scope reference: `docs/PROJECT_SCOPE.md` — CustomContent Engine  

## 1. Objective

Validate the performance feasibility of a BFS-based vein miner algorithm for custom blocks, using the existing architectural primitives (`BlockQuery`, `BudgetView`, `HashSet` for visited tracking).

This spike follows the pattern established in Spike 1 (binaryPdcPerformance) to provide measurable performance data for the `vein_miner` mechanic proposal.

## 2. Scope

Measured vein sizes: 10, 25, 50, 64, 100, 150, 200 blocks.

Measured operations:
- BFS with `HashSet` for visited tracking (O(1) lookup)
- BFS with `ArrayList` for visited tracking (O(n) lookup) — baseline for performance comparison

Parameters tested:
- `max_blocks`: 64 (matches common plugin defaults)
- `max_depth`: 20 (typical vein height limit)

Out of scope:
- Bukkit/Paper event handling overhead
- Actual PDC queries (simulated with in-memory structures)
- Network or persistence costs

## 3. Test Environment

- OS: Windows 10 10.0 amd64
- Java: 21
- Gradle task: `./gradlew veinMinerSpike --no-daemon`
- Warmup iterations per operation: 2,000
- Measured iterations per operation: 8,000
- Allocation measurement: approximate per-thread allocated bytes via `com.sun.management.ThreadMXBean`

## 4. Methodology

The spike simulates BFS vein traversal using synthetic block positions in a linear vein (worst-case for visited tracking). This provides an upper bound on algorithmic cost.

For each vein size:
1. Create synthetic vein positions
2. Warm up both BFS variants
3. Measure average wall-clock time per operation with `System.nanoTime()`
4. Measure approximate thread-local allocation

## 6. Interpretation (to be filled after execution)

Preliminary expectations based on algorithmic analysis:
- `HashSet` should scale O(1) per lookup, making it superior for large veins
- `ArrayList` will degrade to O(n) per lookup, causing quadratic behavior
- Memory overhead for `HashSet` will be higher per entry but with better overall performance
